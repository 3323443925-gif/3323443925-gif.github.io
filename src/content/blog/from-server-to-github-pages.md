## 一台每年续费的服务器

在搬走之前，这个网站跑在一台最小的云服务器上。它有数据库、有后台、有评论插件，也有每月账单、系统补丁和证书续期提醒。

问题不是这些工作有多难，而是它们和写作没有关系。我打开服务器的次数，远远少于我打开编辑器的次数。

## 我真正需要的功能

把需求列出来之后，发现只剩下几条：

- 展示项目与文章
- 让链接可以被分享
- 发布过程足够短
- 不需要我维护运行时

这些需求不需要数据库，也不需要服务端渲染。于是迁移方向变得很清楚：纯静态产物，内容随代码一起版本管理。

## 迁移后的发布流程

现在的流程是：

1. 在本地新建一个 Markdown 文件
2. 填写标题、日期与摘要
3. 提交并推送到默认分支
4. 自动构建，几分钟后线上可见

没有后台登录，没有数据库备份，也没有“服务器又到期了”的邮件。

## 失去了什么

静态站点不是没有代价：

- 没有实时评论，需要接第三方服务
- 搜索要依赖构建期生成的索引
- 内容更新需要经过一次提交

对我来说，这些代价可以接受。评论本来就不多，搜索可以稍后补上，而提交一次代码正是我希望的发布仪式。

## 适合谁

如果你主要写文章、展示作品，并且能接受用 Markdown 写作，静态托管几乎是成本最低的方案。如果你需要用户系统、实时数据或复杂表单，那还是应该老老实实选择服务端方案。

工具没有高下，只有是否匹配当下的事情。
